# Customer Shopping Behaviour Analysis

An end-to-end data analytics project exploring customer purchasing patterns, spending behaviour, product preferences, subscriptions, and discounts using **Python, MySQL, and Power BI**.

## Project Overview

This project demonstrates a practical analytics workflow: prepare customer shopping data in Python, load the cleaned data into MySQL, answer business questions using SQL, and explore results in an interactive Power BI dashboard.

## Tools & Technologies

- **Python:** Pandas for data inspection, cleaning, and feature engineering
- **Jupyter Notebook:** Data preparation and MySQL data loading
- **MySQL:** Business-focused SQL analysis
- **SQLAlchemy & PyMySQL:** Transfer the cleaned dataset from Python to MySQL
- **Power BI:** Interactive dashboard and visualizations

## Data Preparation (Python)

The notebook uses Pandas to:

1. Inspect the dataset with `head()`, `info()`, `describe()`, and missing-value checks.
2. Fill missing **Review Rating** values using the median rating within each product category.
3. Standardize column names to lowercase with underscores and rename `purchase_amount_(usd)` to `purchase_amount`.
4. Create an `age_group` column using age quartiles labelled **Young Adult**, **Adult**, **Middle-Aged**, and **Senior**.
5. Map purchase frequency labels to a numerical `purchase_frequency_days` column.
6. Verify that `discount_applied` and `promo_code_used` match, then drop the redundant promo code column.
7. Load the resulting DataFrame into the MySQL `customer_behaviour.customer` table.

## SQL Business Analysis

The `customer_behaviour.sql` script investigates:

- Revenue generated by each gender
- Customers using discounts whose purchases meet or exceed the overall average purchase amount
- Top five products by average review rating
- Average spending for Standard versus Express shipping
- Customer counts, average spend, and revenue by subscription status
- Products with the highest discount usage rates
- **New**, **Returning**, and **Loyal** customer segments based on previous purchases
- Top three most-ordered products within each category using `ROW_NUMBER()`
- Repeat buyers by subscription status (defined in the SQL as more than five previous purchases)
- Revenue by age group

SQL techniques include **aggregation, GROUP BY, CASE, subqueries, CTEs, and window functions**.

## Power BI Dashboard

The Power BI report, **Customer Behaviour Dashboard**, includes customer-count reporting, subscription breakdown, category comparisons, age-group visuals, and interactive filters for:

Open `Customer_Behaviour_Dashboard.pbix` in Power BI Desktop to explore the dashboard. You may need to update its data-source connection and refresh the report on your computer.

## How to Run

1. Download or clone this repository.
2. Obtain `customer_shopping_behavior.csv` and place it in your project folder.
3. Install the Python dependencies:

   ```bash
   pip install pandas sqlalchemy pymysql jupyter
   ```

4. Start MySQL and create the database:

   ```sql
   CREATE DATABASE IF NOT EXISTS customer_behaviour;
   ```

5. Open `Customer_Shopping_Behaviour_Analysis.ipynb`. Change the CSV path to your local file path (for example, `customer_shopping_behavior.csv`).
6. Configure the notebook's MySQL connection with **your own local credentials**. Do not commit passwords or other secrets to GitHub. The uploaded notebook currently contains a hard-coded local password; **remove it before publishing**.
7. Run the notebook cells to prepare and load the data. **Note:** The current `to_sql(..., if_exists="replace")` command replaces the target table when executed.
8. Open `customer_behaviour.sql` in MySQL Workbench and run the analysis queries.
9. Open the `.pbix` file in Power BI Desktop, configure the appropriate data source if prompted, and refresh.

## Potential Business Applications

The analyses can help explore which customer segments contribute revenue, which products receive higher ratings, how discounts relate to shopping patterns, and how subscriptions and shipping preferences differ across customers.

> **Note:** This repository contains analysis queries and a dashboard, not a validated report of numerical findings. Insights should be interpreted after running the analysis on the dataset.
